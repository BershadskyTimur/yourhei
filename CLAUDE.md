# YourHEI — правила проекта

Полное ТЗ: [SPEC.md](SPEC.md). Сбор данных о заведениях: [DATA_COLLECTION.md](DATA_COLLECTION.md). Ход работы: [PROGRESS.md](PROGRESS.md). Правила Next.js этой версии: [AGENTS.md](AGENTS.md) (перед кодом смотри `node_modules/next/dist/docs/`).

## Главное

- Владелец — новичок в программировании. Объясняй простыми словами, всё, что нужно сделать руками, давай пошаговой инструкцией.
- Работай строго по этапам (SPEC.md, раздел 17). Следующий этап — только по команде владельца. Перед этапом покажи план.
- Противоречие или пробел в ТЗ — спроси, не выдумывай.
- Ход работы веди в `PROGRESS.md`. Коммит в git после каждого законченного шага.
- Этап готов, когда: `npm run build` и `npm run lint` без ошибок, `npm test` проходит, сайт проверен в обеих темах, на мобильной ширине и на всех 5 языках.

## Код

- Стек: Next.js (App Router) + TypeScript strict + Tailwind v4 + next-intl + Supabase + MapLibre.
- **Никаких захардкоженных текстов интерфейса** — только через `messages/<язык>.json`. Ключи во всех 5 файлах совпадают (проверяет тест).
- **Никаких цветов в компонентах** — только токены из `src/app/globals.css` (`bg-bg`, `text-text`, `bg-accent` …). Контраст проверяет `src/config/palette.test.ts`.
- Секреты только в `.env.local` (в git не попадает); описание — в `.env.example`. В браузер можно отдавать только publishable-ключ Supabase, секретный (`service_role`) — никогда.
- Логика подбора и нормализации — чистые функции с юнит-тестами.
- Язык в URL: `/ru`, `/en`, `/ka`, `/es`, `/zh`. Новый язык = файл переводов + строка в `src/config/locales.ts`.
- В Next.js 16 `middleware` называется `proxy` (`src/proxy.ts`). Плагин `next-intl/plugin` не используется (он тянет @swc/core, который не загружается в этом окружении) — алиас задан вручную в `next.config.ts`.
- Данные заведений: не выдумывать; только открытые источники (Wikidata CC0, OpenStreetMap ODbL с атрибуцией) и подтверждённые данные.
