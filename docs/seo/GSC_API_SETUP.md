# Доступ к Search Console через API (инструкция для владельца)

Составлено 18.11.2026. Время: около 15–20 минут, один раз. Деньги не нужны: Search Console API бесплатный.

## Зачем

Сейчас выгрузки из Search Console делаются руками (экспорт, скриншоты). С доступом по API я смогу сам:

- выгружать «Эффективность» (запросы, страницы, страны, устройства, по дням) за весь срок хранения данных, а не 1 000 строк из кнопки «Экспорт»;
- делать «Проверку URL» по списку адресов: Google проиндексировал страницу или нет, когда её последний раз сканировали, какой адрес он выбрал основным, не закрыта ли она `noindex`;
- смотреть, какие карты сайта отправлены и есть ли в них ошибки.

Это заменит часть ручных задач из раздела A в `DEFERRED.md`: «Проверку URL» Гарварда (19–23.11) и выгрузку 01.12.

Чего через API **не будет** (по справочнику Google API, который лежит в навыке `seo-google`, там только эффективность, проверка URL, карты сайта и список ресурсов): отчёта «Статистика сканирования» и списков из «Индексирование → Страницы» («Просканирована, но пока не проиндексирована», «Обнаружена…»). Их по-прежнему нужно выгружать руками. Точнее проверю по документации Google, когда будем писать скрипт.

## Как это работает простыми словами

Мы заводим для меня «служебный аккаунт»: это отдельный робот-пользователь Google без пароля, у которого есть файл-ключ. Вы даёте этому роботу в Search Console право читать данные. Ключ лежит только на вашем компьютере, в git и в чат он не попадает.

## Шаги

### Шаг 0. Узнать, какой у вас ресурс в Search Console

1. Откройте https://search.google.com/search-console
2. Слева вверху нажмите на выпадающий список ресурсов.
3. Посмотрите, как записан сайт:
   - `yourhei.com` без `https://` — это ресурс «Домен»;
   - `https://www.yourhei.com/` — это ресурс «Префикс URL».
4. Запомните запись в точности, она понадобится в шаге 7. (По `PROGRESS.md`, Bing подтвердился импортом из Search Console с адресом `yourhei.com`, похоже, это «Домен». Но проверьте.)

### Шаг 1. Создать проект в Google Cloud

1. Откройте https://console.cloud.google.com и войдите тем же аккаунтом Google, которым пользуетесь в Search Console.
2. Если Google просит принять условия, примите их сами.
3. Сверху нажмите на выбор проекта → «Новый проект». Название: `YourHEI SEO`. Организацию не выбирайте, если её нет. Нажмите «Создать» и дождитесь, пока проект появится и будет выбран сверху.
4. Если Google потребует привязать банковскую карту, остановитесь и напишите мне. Для этой задачи карта не нужна.

### Шаг 2. Включить Search Console API

1. В меню слева: «API и сервисы» → «Библиотека».
2. В поиске введите `Google Search Console API`, откройте её.
3. Нажмите «Включить».

### Шаг 3. Создать служебный аккаунт

1. В меню слева: «IAM и администрирование» → «Сервисные аккаунты» → «Создать сервисный аккаунт».
2. Название: `yourhei-seo`. Нажмите «Создать и продолжить».
3. Роли не выбирайте (пропустите шаг), нажмите «Продолжить», затем «Готово».
4. В списке появится строка с адресом вида `yourhei-seo@<что-то>.iam.gserviceaccount.com`. Скопируйте его, он нужен в шаге 6.

### Шаг 4. Скачать ключ

1. Нажмите на этот служебный аккаунт → вкладка «Ключи» → «Добавить ключ» → «Создать ключ».
2. Тип: JSON → «Создать». В «Загрузки» скачается файл `.json`.
3. Если Google пишет, что создание ключей запрещено политикой организации, остановитесь и напишите мне текст ошибки.

### Шаг 5. Положить ключ в безопасное место

Положите файл **вне папки проекта**, чтобы он никогда не попал в git. В PowerShell (подставьте настоящее имя скачанного файла):

```powershell
New-Item -ItemType Directory -Force "$HOME\.config\claude-seo"
```

```powershell
Move-Item "$HOME\Downloads\ИМЯ-СКАЧАННОГО-ФАЙЛА.json" "$HOME\.config\claude-seo\service_account.json"
```

Содержимое файла не открывайте для пересылки, не вставляйте в чат и не отправляйте по почте.

### Шаг 6. Дать роботу доступ к Search Console

1. В Search Console выберите ваш ресурс (из шага 0).
2. «Настройки» → «Пользователи и разрешения» → «Добавить пользователя».
3. Вставьте адрес служебного аккаунта из шага 3.
4. Разрешение: «Полное». «Владелец» не нужен.
5. Нажмите «Добавить».

### Шаг 7. Сообщить мне

Напишите мне одним сообщением:

- «Ключ лежит в `~/.config/claude-seo/service_account.json`»;
- как записан ваш ресурс (из шага 0).

Больше ничего слать не нужно. Дальше я сам:

1. напишу небольшой скрипт `scripts/gsc-export.mjs` (по образцу `scripts/indexnow.mjs`, на Node без новых пакетов, только чтение);
2. допишу в `.env.example` два параметра (путь к ключу и имя ресурса), в `.env.local` пропишу их у вас;
3. проверю связь на данных за последние дни и положу первую выгрузку в `docs/seo/gsc-<дата>/`;
4. запишу итог в `PROGRESS.md`.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `403` при запросе данных | Адрес служебного аккаунта не добавлен в Search Console, или добавлен не к тому ресурсу (шаги 0 и 6) |
| `404` на ресурс | Неверно записан ресурс: «Домен» пишется как `sc-domain:yourhei.com`, «Префикс URL» с `https://` и косой чертой на конце |
| «API не включён» | Повторить шаг 2 в том же проекте |
| Не создаётся ключ | См. шаг 4 |

## Безопасность

- Ключ лежит только на вашем компьютере вне проекта; `.env*` в git не попадает (`.gitignore`), сам ключ в проекте не хранится.
- Скрипт будет просить только право чтения (`webmasters.readonly`).
- Если ключ мог утечь: в Google Cloud откройте служебный аккаунт → «Ключи» → удалите ключ; в Search Console удалите этого пользователя. Доступ пропадёт сразу.
