# YourHEI — пошаговая инструкция для владельца (этап 1)

Здесь всё, что нужно сделать руками: открыть сайт у себя на компьютере, подключить базу данных (Supabase) и выложить сайт в интернет (Vercel). Делайте по порядку. Если что-то не получается — пришлите скриншот или текст ошибки.

Все команды ниже вводятся в **PowerShell** (кнопка Пуск → наберите `PowerShell` → Enter) и выполняются в папке проекта. Чтобы перейти в неё, сначала введите:

```powershell
cd "C:\Users\Timur Dimitriev\Documents\YourHEI"
```

---

## Часть 1. Открыть сайт у себя на компьютере

1. Запустите сайт:

   ```powershell
   npm run dev
   ```

   Через несколько секунд появится строка `Local: http://localhost:3000`. Окно PowerShell не закрывайте — пока оно открыто, сайт работает.

2. Откройте в браузере адрес **http://localhost:3000** — вас перенаправит на сайт на языке вашего браузера.

3. Чтобы остановить сайт, в окне PowerShell нажмите `Ctrl + C`.

Без базы данных сайт уже работает: он берёт 45 тестовых заведений из файла `data/seed/institutions.json`.

## Часть 2. Подключить Supabase (базу данных)

### 2.1. Создайте проект

1. Откройте https://supabase.com → **Start your project** → войдите через GitHub (проще всего).
2. Нажмите **New project**. Заполните:
   - **Name:** `yourhei`
   - **Database Password:** придумайте надёжный пароль и **сохраните его** в менеджере паролей (потом он вряд ли понадобится, но восстановить его нельзя, только сбросить).
   - **Region:** `Central EU (Frankfurt)` — ближе всего к Грузии и Казахстану.
   - Тариф **Free**.
3. Нажмите **Create new project** и подождите 1–2 минуты, пока проект подготовится.

### 2.2. Создайте таблицы

1. В левом меню откройте **SQL Editor** → **New query**.
2. Откройте на своём компьютере файл `supabase\migrations\0001_stage1.sql` (в Блокноте), выделите всё (`Ctrl + A`), скопируйте (`Ctrl + C`).
3. Вставьте в окно запроса в Supabase (`Ctrl + V`) и нажмите **Run**.
4. Внизу должно появиться **Success. No rows returned**.

### 2.3. Загрузите тестовые заведения

1. Снова **New query**.
2. Скопируйте всё из файла `supabase\seed.sql`, вставьте, нажмите **Run**.
3. Должно появиться **Success**.
4. Проверка: левое меню **Table Editor** → таблица `institutions` — в ней должно быть **45 строк**.

### 2.4. Возьмите два значения (ключи)

1. Левое меню → **Project Settings** (шестерёнка внизу) → **API Keys** (или просто **API**).
2. Вам нужны два значения:
   - **Project URL** — адрес вида `https://abcdefgh.supabase.co`;
   - **Publishable key** (начинается с `sb_publishable_…`). На старых проектах он называется **anon public** — это то же самое.
3. ⚠️ Ключ **secret / service_role** не нужен и **никому не показывайте**, в сайт его не вставляйте.

### 2.5. Положите ключи в проект

1. Скопируйте шаблон:

   ```powershell
   Copy-Item .env.example .env.local
   ```

2. Откройте файл в Блокноте:

   ```powershell
   notepad .env.local
   ```

3. После `NEXT_PUBLIC_SUPABASE_URL=` вставьте Project URL, после `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=` — publishable key. Без пробелов и кавычек. Сохраните файл (`Ctrl + S`).
4. Файл `.env.local` не попадает в интернет (он закрыт в `.gitignore`) — это нормально и правильно. **Не отправляйте его содержимое в чат.**

### 2.6. Проверьте подключение

1. Остановите сайт (`Ctrl + C`) и запустите заново: `npm run dev`.
2. Откройте http://localhost:3000.
3. В окне PowerShell должна появиться строка:
   `[institutions] loaded 45 from Supabase`
   Если там написано `from local test file` — ключи не подхватились: проверьте названия переменных и перезапустите.

## Часть 3. Выложить сайт в интернет (GitHub + Vercel)

### 3.1. Загрузите код на GitHub

1. Откройте https://github.com/new. **Repository name:** `yourhei`. Выберите **Private** (закрытый). Ничего не добавляйте (ни README, ни .gitignore). Нажмите **Create repository**.
2. На открывшейся странице скопируйте адрес репозитория вида `https://github.com/ВАШ_ЛОГИН/yourhei.git`.
3. В PowerShell (в папке проекта) выполните, подставив свой адрес:

   ```powershell
   git remote add origin https://github.com/ВАШ_ЛОГИН/yourhei.git
   git push -u origin main
   ```

4. При первом запуске откроется окно входа в GitHub — войдите. После этого на странице репозитория появятся файлы.

### 3.2. Подключите Vercel

1. Откройте https://vercel.com → **Sign Up** → **Continue with GitHub**. Выберите бесплатный тариф **Hobby** (он для некоммерческих проектов — пока на сайте нет рекламы, это подходит; перед запуском рекламы тариф нужно будет пересмотреть, я напомню на этапе 6).
2. Нажмите **Add New… → Project**. Найдите репозиторий `yourhei` → **Import** (если его не видно — нажмите «Adjust GitHub App Permissions» и дайте доступ к репозиторию).
3. Framework Preset должен определиться сам: **Next.js**. Ничего не меняйте.
4. Раскройте **Environment Variables** и добавьте две переменные (имя → значение — те же, что в `.env.local`):
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
5. Нажмите **Deploy** и подождите 2–3 минуты. Появится ссылка вида `https://yourhei-….vercel.app`.

### 3.3. Проверьте опубликованный сайт

Откройте ссылку и пройдите чек-лист из конца этого файла.

# Этап 2 «Аккаунты»: что сделать руками

Выполняйте по порядку. Всё делается в Supabase (в браузере), кроме проверки в конце.

## Часть 4. Обновить базу данных

1. Supabase → **SQL Editor** → **New query**. Скопируйте всё из файла `supabase\migrations\0002_accounts.sql`, вставьте, нажмите **Run**. Ожидаемо: **Success. No rows returned**.
2. Снова **New query**. Скопируйте всё из `supabase\migrations\0003_reference_data.sql` (список стран, регионы, возрастные пороги), нажмите **Run**. Ожидаемо: **Success**.
3. Проверка: **Table Editor** → таблица `countries` (249 строк), `regions` (3), `country_age_thresholds` (около 35 строк). Новый запрос `select public.min_age_for('GE');` должен вернуть **16**, а `select public.min_age_for('KZ');` — **14**.

> Порядок важен: сначала 0002, потом 0003. Если запустили 0003 первым, будет ошибка «relation does not exist» — просто запустите 0002 и потом 0003 ещё раз. Оба файла можно запускать повторно без вреда.

## Часть 5. Настроить вход и письма в Supabase

Названия пунктов меню в Supabase иногда меняются; если не нашли — пришлите скриншот.

1. **Authentication → URL Configuration:**
   - **Site URL:** `http://localhost:3000` (пока вы проверяете у себя).
   - **Redirect URLs** → **Add URL**: добавьте `http://localhost:3000/**` и адрес вашего сайта на Vercel с `/**` на конце, например `https://yourhei-xxxx.vercel.app/**`. Без этого ссылка из письма не сработает.
2. **Authentication → Sign In / Providers → Email:** вход по почте должен быть включён, **Confirm email** — включён (так по умолчанию). Если есть поле **Minimum password length**, поставьте **10**.
3. ⚠️ **Лимит писем.** Встроенная почта Supabase отправляет очень мало писем в час (порядка двух) — для проверки хватит, для настоящих пользователей нет. Перед запуском нужно будет подключить свою почтовую службу (например, Resend; нужен свой домен). Я напомню на этапе 6.

## Часть 6. Проверить регистрацию самому

1. `npm run dev`, откройте http://localhost:3000/ru/register.
2. Пройдите 4 шага со своей настоящей почтой. Можно использовать вторую почту или алиас вида `имя+test1@gmail.com`.
3. После «Создать аккаунт» откройте письмо и нажмите на ссылку — вы попадёте в профиль с надписью «Почта подтверждена».
4. В Supabase → **Table Editor** → `profiles`: должна появиться ваша строка (дата рождения, страна и т. д.), в `user_documents` — ваши документы.
5. В профиле измените что-нибудь и нажмите **Сохранить**; нажмите **Скачать мои данные** — скачается файл `yourhei-my-data.json`.
6. Проверка возрастного порога: откройте окно инкогнито, начните регистрацию, выберите страну проживания **Грузия** и дату рождения «15 лет назад» — на шаге 2 появится вежливый отказ, а в `auth → Users` и `profiles` ничего не создастся.
7. Проверка сброса пароля: на странице входа «Забыли пароль?».
8. **Удаление аккаунта** (в самом конце, на тестовой записи): профиль → «Удалить аккаунт и все данные». Строка должна исчезнуть из `profiles` и из **Authentication → Users**.

## Часть 7 (этап 3). Включить опрос

1. Supabase → **SQL Editor** → **New query**. Скопируйте всё из файла `supabase\migrations\0004_survey.sql`, вставьте, нажмите **Run**. Ожидаемо: **Success. No rows returned**. Файл можно запускать повторно.
2. Проверка: **Table Editor** → таблица `survey_attempts` (пока пустая).
3. Откройте http://localhost:3000/ru/profile → карточка «Пройдите опрос для подбора» → **Перейти к опросу**.
4. Пройдите опрос до конца. После каждого ответа строка в `survey_attempts` обновляется (колонка `answers`). Закройте вкладку на середине и вернитесь: появится «Продолжить с того места, где остановились».
5. После «Завершить» статус строки станет `completed`. Теперь опрос изменить нельзя, можно только «Пройти опрос заново».

## Часть 8 (подбор). Данные и подборка

Порядок важен. Каждый SQL выполняется так же: **SQL Editor → New query → вставить → Run**.

1. `supabase\migrations\0005_programs.sql` — таблицы программ, стипендий, рейтингов, источников и данных по странам. Ожидаемо: **Success. No rows returned**.
2. Четыре файла `supabase\data\institutions_region_01.sql` … `_04.sql` — **599 вузов и колледжей** 12 стран региона (Армения, Азербайджан, Беларусь, Грузия, Казахстан, Кыргызстан, Молдова, Россия, Таджикистан, Туркменистан, Узбекистан, Украина). Выполните каждый файл отдельно (порядок любой). Заведения, которые уже есть в базе, повторно не добавляются.
3. Откройте `docs\review\REVIEW.md` и **прочитайте**: там данные трёх вузов Грузии (университет Ильи, IBSU, Тбилисский медицинский университет) с источниками и пометками, что сомнительно.
4. Если всё верно, выполните `supabase\data\drafts_published.sql` — тогда эти данные станут публичными и попадут в подборку. Если хотите сначала только сохранить, выполните `supabase\data\drafts.sql` (скрытые черновики).
5. Откройте **http://localhost:3000/ru/matches** (после опроса). Для проверки пройдите опрос так: уровень «Бакалавриат», языки — английский B2, страны в профиле — Грузия, специальность «Разработка программного обеспечения» (0613) или «Электроника» (0714).

Проверка в Table Editor: `institutions` (около 640 строк), `programs` (25 строк после шага 4), `country_data` (1 строка, `GE`).

## Часть 9. Оформление, языки, админ-панель

- **Полный список файлов для Supabase по порядку** (включая `0006_admin.sql` и как стать админом) — в файле `docs\SUPABASE_FILES.md`. Если запутались — пройдите его с начала, все файлы безопасно запускать повторно.
- В `.env.local` можно добавить `NEXT_PUBLIC_CONTACT_EMAIL=ваша@почта` — адрес появится на странице «Контакты».
- Языки сайта: русский, английский, грузинский, испанский, китайский, украинский, армянский, казахский. Тексты украинского, армянского, казахского (и грузинского, испанского, китайского) переведены автоматически — перед запуском покажите носителям языка.
- Юридические тексты (политика конфиденциальности и условия) написаны в широкой формулировке (аналитика, передача любым третьим лицам, любое использование данных). Такая формулировка может противоречить законам о защите данных (GDPR и др.): перед запуском покажите юристу. Когда подключите аналитику или рекламу — нужен баннер согласия на cookie.
