# Безопасность YourHEI: что уже сделано и что включить вручную

## Что уже есть в коде (проверено)

- **База закрыта правилами (RLS).** У всех 17 таблиц включена защита строк. Посетитель видит только публичные данные (заведения, опубликованные программы), человек — только свои строки (профиль, документы, опросы, «Мой список»). Писать в каталог может только администратор.
- **Нельзя дать себе роль админа через сайт.** Колонка `role` недоступна для изменения публичным ключом; админом делает только SQL-команда в Supabase.
- **Секретный ключ не в коде.** Проверил историю git и файлы: ключей `service_role` нет. В Vercel он не добавлен.
- **Ссылки из данных безопасны.** Любая ссылка (сайт вуза, «Подать заявку») показывается только если начинается с `http://` или `https://`; `javascript:` и подобное отбрасывается (тест `safe-url.test.ts`).
- **Политика безопасности браузера (CSP) и заголовки.** Браузер грузит скрипты, данные и фреймы только с нужных адресов (Supabase, карта OpenFreeMap, Turnstile, Google Analytics). Запрещены встраивание сайта в чужие страницы и внешние формы. Также включены HSTS, запрет определения типа файла, ограничение Referrer и устройств (камера, микрофон, геолокация).
- **Защита входа:** пароль не короче 10 символов с буквой и цифрой, проверка на частые пароли; одинаковый ответ в «Забыли пароль» (нельзя выяснить, есть ли такая почта); переадресации после входа только внутри сайта; проверка возраста; можно включить капчу Turnstile (`docs/DEPLOY.md`, раздел 6).
- **Аналитика без личных данных:** только анонимные просмотры страниц и только после «Принять все»; адреса IP не хранятся; в базу они пишутся без имён и почт.
- **Зависимости:** `npm audit` — 0 уязвимостей.

## Что нужно включить вручную в Supabase (10 минут)

Откройте Supabase → ваш проект:

1. **Authentication → Sign In / Providers → Email:**
   - **Minimum password length** = `10`;
   - включите **Prevent use of leaked passwords** (если есть в вашем тарифе: проверка пароля по базе утёкших) — на бесплатном тарифе пункта может не быть;
   - **Confirm email** — включён (для настоящих пользователей).
2. **Authentication → Attack Protection:** включите **CAPTCHA protection** (Turnstile; см. `docs/DEPLOY.md`, раздел 6).
3. **Authentication → Rate Limits:** оставьте значения по умолчанию или уменьшите; после подключения своей почты можно повысить лимит писем.
4. **Двухфакторная защита вашего аккаунта админа:** зайдите на сайт → профиль Supabase (иконка внизу слева → Account → Security) и включите двухфакторную защиту для аккаунта на supabase.com. Для самого сайта: Authentication → **Multi-Factor** (можно включить TOTP).
5. **Settings → API:** убедитесь, что «Exposed schemas» — только `public` (так по умолчанию), и что секретный ключ `service_role` вы никуда не копировали, кроме `.env.local` на время загрузки данных.
6. **Database → Backups** (платный тариф) или раз в неделю делайте экспорт: **Table Editor → таблица → Export** для `profiles`, `favorites`, `programs`.

## В Vercel

- Не добавляйте переменные без префикса `NEXT_PUBLIC_`, кроме тех, которые действительно секретные; секретные помечайте типом **Secret**.
- Включите **Settings → Security → Attack Challenge Mode** только если на сайт идёт атака (иначе отпугнёт людей).
- Включите защиту вашего аккаунта GitHub и Vercel двухфакторной проверкой (GitHub → Settings → Password and authentication). Через GitHub можно изменить код сайта, поэтому это самое важное.

## Известные ограничения

- Формулировки политики конфиденциальности очень широкие: перед запуском покажите юристу.
- Счётчик посещаемости считает только согласившихся на аналитику, реальные цифры выше.
- Из админ-панели нельзя удалить пользователя (только он сам себя): при необходимости делается в Supabase → Authentication → Users.
