## Подбор и данные (этап 5 + часть этапа 4) — код готов; нужны SQL-файлы 0005 и данные

**Статус:** типы, линтер, 280 юнит-тестов, сборка, 116 браузерных проверок — зелёные. На настоящей базе не проверено: нужно выполнить `0005_programs.sql`, четыре файла заведений и `drafts_published.sql` ([docs/SETUP_GUIDE.md](docs/SETUP_GUIDE.md), часть 8). Порядок по решению владельца: сначала движок, потом данные; базу расширять новыми странами; сбор по официальным сайтам по правилам DATA_COLLECTION.md разрешён.

### Движок подбора (`src/lib/matching/`, чистые функции, 57 тестов)
- **Жёсткие фильтры** (раздел 11): уровень; страна и тип из профиля; язык обучения (из названных языков, самооценка B2+ или сертификат B2+, либо готовность к подготовительному году); формат (совпадение или «смешанный»); «только бесплатно» — только подтверждённо бесплатные (неизвестная цена не считается бесплатной); бюджет с запасом ×1,15 с пересчётом валют; месяц набора; программы «далеко ниже требований» (больше 15 баллов) не показываются.
- **Баллы 0–100, 7 компонентов:** соответствие требованиям (оценки, экзамены, языковые сертификаты; сертификаты из списка — альтернативы, берётся лучший), специальность (одинаковая детальная = 100, узкая = 70, широкая = 40; 2-е и 3-е пожелание весят ×0,9 и ×0,8), престиж (по рейтингу нужного вида), предпочтения (форма, размер, город, климат), дополнительное (практика, двойной диплом, обмен), жизнь (общежитие, работа во время и после учёбы, признание диплома), запас по бюджету (учёба и жизнь). Базовые веса 20/25/8/10/5/12/20; три приоритета из опроса усиливают свои компоненты в 2 / 1,75 / 1,5 раза. **Компонент без данных исключается, веса остальных перенормируются; в интерфейсе — «Нет данных по …».**
- **Группы:** «надёжные» (все сравнимые требования выполнены с запасом ≥ 10 баллов), «подходящие» (выполнены), «амбициозные» (чуть ниже). Ответ о стратегии меняет, сколько показывать в каждой группе (10/6/2, 6/6/4, 3/6/8).
- **«Почему подходит»** (до 3 лучших компонентов) и **«Чего не хватает»** («нужен IELTS 6.5, у вас 6.0», недостающий экзамен, подготовительный год, превышение бюджета) — по шаблонам на 5 языках, без ИИ. Интерфейс `ExplanationProvider` заложен для платной версии.
- **Курсы валют:** `/api/rates` (бесплатный источник open.er-api.com, кэш на сутки, при сбое — запасная таблица с пометкой «приблизительно»).
- **Страница `/matches`:** из последнего завершённого опроса и профиля строит подборку; ссылки в шапке («Моя подборка») и на экране завершения опроса. Если проверенных программ нет — честно пишет «данные добавляются».

### Данные
- **База** (`0005_programs.sql`): `programs`, `scholarships`, `rankings`, `sources`, `country_data`, новые поля заведений (размер, климат, город, общежитие, особенности). Публике видны только строки со статусом `published`.
- **Расширение базы заведений:** `scripts/fetch-wikidata.mjs` собрал **599 вузов и колледжей** 12 стран (Армения, Азербайджан, Беларусь, Грузия, Казахстан, Кыргызстан, Молдова, Россия, Таджикистан, Туркменистан, Узбекистан, Украина) из Wikidata; 4 SQL-файла по 150 записей (`supabase/data/institutions_region_0*.sql`). **51 заведение на спорных территориях** (Крым, Абхазия, Южная Осетия, Приднестровье, Донецкая и Луганская области; границы заданы приблизительными рамками) исключено и не загружено; список в `data/seed/wikidata-region.json` (`droppedDisputed`). Решение по ним за владельцем.

Грузия: валюта, начало учебного года, ссылка на ВНЖ для учёбы; правило о работе студентов оставлено пустым — источник не прочитан полностью.

### Не сделано

2. **Страница карточки заведения** с программами, стоимостью и поступлением (раздел 12): пока временная страница с базовыми данными.
3. **Результаты подбора не сохраняются** в таблице `match_results` (раздел 11), они пересчитываются при каждом открытии. Сохранение, избранное, сравнение, чек-лист документов и напоминания о дедлайнах — следующие шаги этапа 5.
4. **Данных мало:** 25 программ в 3 вузах одной страны. Остальные ~600 заведений есть только на карте; чтобы подбор заработал для других стран, нужны новые партии по DATA_COLLECTION.md (5–10 заведений за сессию).

6. Вход через Google, капча, свои письма — по-прежнему отложены.

## Этап 3 «Опрос» — код готов и проверен; нужен один SQL-файл (`0004_survey.sql`)

**Статус:** типы, линтер, 211 юнит-тестов, сборка, 150 браузерных проверок (десктоп + мобильный) — всё зелёное. На настоящей базе не проверено: нужно выполнить `supabase/migrations/0004_survey.sql` и пройти опрос самому ([docs/SETUP_GUIDE.md](docs/SETUP_GUIDE.md), часть 7).

### Изменения по решению владельца (порядок «аккаунт → профиль → опрос»)
- **Регистрация теперь из двух шагов:** «Возраст» (дата рождения, страна проживания, галочка) и «Аккаунт» (почта, пароль, согласие). Возрастной порог по-прежнему защищён до создания аккаунта (раздел 6 ТЗ), в форме и в базе.
- **Профиль** (`/profile`) хранит всё остальное и меняется в любое время: «О себе» (дата рождения, страна, пол — необязательно, гражданства), «Что вы ищете» (регионы, страны, типы), «Документы». Сохранять можно по частям: обязательны только дата рождения и страна проживания. Пока профиль не заполнен, показывается подсказка.
- **Опрос — после профиля.** Завершённый опрос изменить нельзя, можно только пройти заново (каждое прохождение — отдельная «попытка»). Это отличается от раздела 10 ТЗ («ответы можно изменить позже») по решению владельца.

### Сделано
- **Движок на конфиге** (`src/lib/survey/config.ts`, `engine.ts`): 44 вопроса с условиями показа, обязательностью, назначением (фильтр / баллы / информация); чистые функции (какие вопросы показать, проверка ответа, прогресс, «пропустить все необязательные», очистка ответов скрытых вопросов) + 34 теста. Версия конфига (`SURVEY_VERSION = 1`) сохраняется в каждой попытке.
- **Сколько вопросов:** обязательных 14 (бакалавриат, магистратура, PhD, колледж), 15 (школа), 9 (языковые курсы); необязательные (до ~19) можно пропустить одной кнопкой. Типичный абитуриент отвечает на 14–20, ТЗ покрыто полностью.
- **Справочники** (`src/lib/survey/references.ts`, `data/reference/isced-f.json`): специальности ISCED-F 2013 (11 широких, 29 узких, 80 детальных направлений, названия на 5 языках), 9 систем оценок, 21 экзамен со шкалами, 15 языковых сертификатов с переводом в уровни CEFR, 18 предметов, 10 школьных профилей, 23 валюты, 184 языка (ISO 639-1, названия средствами браузера).
- **Нормализация оценок и экзаменов** в 0–100 (`normalize.ts`, прямая линия, немецкая шкала и Abitur перевёрнуты, значения вне шкалы отклоняются) + тесты. В интерфейсе подписано «приблизительно».
- **Мини-тест RIASEC** (`riasec.ts`): 12 моих формулировок (по 2 на тип), оценка 1–5, итог — 3 предложенных специальности (две из сильнейшего типа и одна из второго), все принимаются по умолчанию, можно оставить любые, но не меньше одной.
- **Интерфейс** (`/survey`): стартовая страница (начать / продолжить / отказаться / список пройденных), по одному вопросу на экране, полоса прогресса, «Назад», «Пропустить», «Пропустить все необязательные», сохранение после каждого ответа, «Сохранить и продолжить позже»; выбор специальности деревом и поиском с приоритетом 1–3; строки для языков, экзаменов, предметов, олимпиад; приоритеты (ровно 3).
- **База** (`supabase/migrations/0004_survey.sql`): таблица `survey_attempts` (ответы в `jsonb`, статус `in_progress / completed / abandoned`, версия конфига). Права: человек видит и создаёт только свои попытки, менять может только незавершённую; завершённая «замораживается» (правило доступа + триггер ставит дату завершения); одна незавершённая попытка на человека.
- Все тексты опроса (около 500 строк) — на 5 языках; перевод на грузинский, китайский и испанский мой, нужна проверка носителями.

### Не сделано / отложено
1. **Подбор заведений после опроса** — это этап 5. Сейчас после опроса человек видит «опрос пройден; подходящие заведения появятся на следующем этапе». Ответы уже хранятся в формате, готовом для подбора (`chosenFields`, нормализация, назначение вопросов).
2. Вход через Google и капча Turnstile — всё ещё отложены (см. этап 2).
3. Опрос ещё не включён в экспорт «Скачать мои данные» (раздел 14/16): добавить вместе с этапом 4.
4. Сертификаты, экзамены, национальные шкалы: границы и перевод в CEFR заданы мной по общедоступным таблицам и помечены приблизительными; Грузинские единые национальные экзамены, CSAT и DET стоит сверить с официальными источниками.

## Этап 2 «Аккаунты» — почта и пароль готовы, вход через Google отдельным шагом

> Обновление: регистрация сокращена до двух шагов («Возраст» и «Аккаунт»), остальное перенесено в профиль (см. этап 3). Описание ниже даёт состояние на момент написания этапа 2.

**Статус:** весь код почты и пароля написан и проверен (типы, линтер, 129 юнит-тестов, 64 браузерных, сборка). Не проверено на настоящей базе: нужно выполнить два SQL-файла и пройти регистрацию самому ([docs/SETUP_GUIDE.md](docs/SETUP_GUIDE.md), части 4–6). Вход через Google и капча не сделаны, см. ниже.

### Сделано
- **База** (`supabase/migrations/0002_accounts.sql`, `0003_reference_data.sql`): справочники `countries`, `regions`, `region_countries`, `country_age_thresholds`, функция `min_age_for()`; `profiles` (дата рождения, пол, страна проживания, гражданства, цели поиска, `plan`, `role`, согласия), `user_documents`. Правила доступа (RLS): человек видит и меняет только свои строки; роль и тариф сам изменить не может (права на UPDATE выданы только на нужные колонки). Триггер при регистрации проверяет данные и **отменяет создание аккаунта, если возраст ниже порога** (запасная защита за проверкой в форме); тот же порог проверяется при редактировании профиля. Функция `delete_my_account()` удаляет вход и все данные пользователя (каскадом).
- **Справочник стран**: 249 кодов ISO 3166-1 (без Косова, по решению владельца) + подрегионы ООН (M49) и три стартовых макрорегиона; файлы `data/reference/*.json` собираются скриптом `scripts/build-reference.mjs`. Тайвань (TW) — «Тайвань / Taiwan», Восточная Азия, без политических формулировок.
- **Мастер регистрации** (4 шага, полоса прогресса, всё на 5 языках): регионы → страны (по умолчанию все, группы по подрегионам, «выбрать все / снять все») → типы; дата рождения, пол, страна проживания, гражданства, галочка возраста с порогом страны; 10 документов со статусами; почта, пароль, согласие, необязательная рассылка. Рядом с каждым личным полем объяснено, зачем оно нужно. До создания аккаунта ответы лежат в браузере (пароль не сохраняется никогда); при отказе по возрасту и после регистрации браузер очищается.
- **Возрастной порог** (чистые функции + тесты): Грузия, ЕС/ЕЭЗ, Великобритания, Швейцария — 16; Индия — 18; остальные — 14. Все значения помечены «требует юридической проверки».
- **Пароль**: не короче 10 символов, буква и цифра, не из списка частых, не содержит имя из почты; показываются все проблемы сразу.
- **Вход, выход, подтверждение почты, сброс пароля** через Supabase Auth (`/login`, `/forgot-password`, `/reset-password`, `/auth/callback`). Кнопка в шапке меняется на «Профиль / Выйти».
- **Профиль** (`/profile`): правка всех данных (те же компоненты, что в мастере), документы, рассылка, «Скачать мои данные» (JSON), «Удалить аккаунт и все данные» с подтверждением; заглушка «Опрос скоро».
- **Политика конфиденциальности и условия**: полноценные шаблоны на 5 языках (7 и 6 разделов) с пометкой «требует проверки юристом».
- Тесты: Vitest — возраст, пароль, страны, документы, схема формы, переводы; Playwright — мастер (ошибки, предвыбор стран, Тайвань, сохранение после перезагрузки, возрастной отказ, регистрация с подменой Supabase, слабый пароль), вход, сброс, профиль, ссылка из письма, безопасность редиректа, 5 языков.

### Решения (этап 2)
- **Одна галочка согласия** с политикой и условиями (в ТЗ они вместе); в базе сохраняются обе отметки времени.
- **Строка «Аттестат / диплом»** в форме одна (как в ТЗ), но человек указывает, что именно; в базе это два кода (`school_certificate`, `diploma`), как в DATA_COLLECTION.md. Для проверки документов на этапе 5 оба кода считаются «документом об образовании».
- **Данные мастера едут в метаданных регистрации** (`user_metadata.wizard`), а триггер в БД создаёт профиль. Так возрастной порог нельзя обойти с телефона и ничего не теряется, пока почта не подтверждена.
- Справочник стран пока читается из файлов, а не из БД (таблицы в БД уже есть, правка в админке — этап 4).
- Вход через Google и капча — не сделаны (ниже).

### Не сделано / отложено
1. **Вход через Google** (решение владельца: «отдельно»). Нужен проект в Google Cloud; при входе через Google профиль создаётся пустым (триггер это поддерживает), данные мастера из браузера нужно дописать после возврата, а при возрасте ниже порога удалить аккаунт.
2. **Капча Turnstile** — не подключена (владелец не выбрал). Supabase умеет проверять её сам; подключим вместе с Google или перед запуском.
3. **Письма:** встроенная почта Supabase даёт примерно два письма в час. Перед запуском нужна своя почтовая служба (Resend + домен).
4. **Ограничение частоты запросов:** для входа, регистрации и сброса пароля работают встроенные лимиты Supabase Auth; отдельных лимитов на нашей стороне пока нет (понадобятся для жалоб и форм обращения на этапе 4).
5. Все возрастные пороги и тексты политики/условий — на проверку юристом.

### Исправление 2026-10-05: «после регистрации не работает Сохранить»
- Причина: в Supabase владельца не были выполнены `0002_accounts.sql` и `0003_reference_data.sql` (таблиц `profiles`, `user_documents`, `countries` нет). Аккаунт создался без профиля, сохранять было некуда.
- В коде: профиль показывает ошибку, если его не удалось загрузить; «Сохранить» больше не пишет «Сохранено», когда в базе ничего не изменилось. `0002` при запуске создаёт пустой профиль для аккаунтов, заведённых раньше.

### Решения
- **Вторая страна — Казахстан**, провайдер карты — **OpenFreeMap** (по ответам владельца). Тестовые данные хранятся в Supabase.
- **База открыта на чтение для всех строк `institutions`** (ТЗ, раздел 12: на карте показываются базовые данные и без проверенной карточки). Записи в БД через публичный ключ невозможны; админ-права — этап 4. Черновые данные карточек будут жить в отдельной таблице `drafts` (раздел 16), а не в `institutions`.
- Цвет и иконка типа пока заданы в коде и в CSS-токенах (`--type-*`), в БД они продублированы (`institution_types`). На этапе 4 справочник станет редактируемым — тогда источник истины переедет в БД.
- Страница `/institutions/...` на этапе 1 — заглушка, не полноценная карточка.
- Плагин `next-intl/plugin` не используется: он грузит `@swc/core`, который в этом окружении не стартует (приложение Claude выдало своей песочнице права на `AppData\Local`, и SWC отказывается хранить там кэш). Алиас `next-intl/config` задан вручную в `next.config.ts`; для наших задач этого достаточно.
- Воркер MapLibre копируется в `public/maplibre/` скриптом перед `dev`/`build` (сборщик не умеет подключать его сам). Папка в git не хранится.
- Эмодзи/иконки: набор из 6 простых иконок нарисован вручную (`src/lib/institutions/icons.ts`), одни и те же пути для легенды и для карты.

### Открытые вопросы владельцу
1. **Спорные территории.** Из тестовых данных я убрал Абхазский и Южно-Осетинский государственные университеты (раздел 5: решать вам). Вопрос шире: как подписывать такие территории и какие границы показывать на карте (OpenFreeMap рисует границы по данным OSM).
2. **Нет точек для трёх типов** (языковые школы, подготовительные программы, техникумы): в Wikidata для Грузии и Казахстана таких записей нет, сервис OpenStreetMap (Overpass) во время работы не отвечал. Счётчики показывают 0. Данные подберём на этапе 4 (импорт из OSM) или соберём по DATA_COLLECTION.md.
3. **Переводы** на грузинский, китайский и испанский сделал я; перед запуском их стоит показать носителям. Названия городов в тестовых данных пока только на английском (на других языках показываются по-английски).
4. **Контакты поддержки:** нужен адрес почты для страницы «Контакты» (форма — позже).
5. **Доступность карты с клавиатуры.** Точки на карте (canvas) не выбираются клавишей Tab; альтернатива — поиск со списком подсказок (работает с клавиатуры). Полноценный список заведений рядом с картой можно добавить позже.

### Известные ограничения
- Supabase отдаёт максимум 1000 строк за запрос; для десятков тысяч точек (этап 6) нужна загрузка по видимой области или векторные тайлы.
- Страница главной обновляется раз в час (`revalidate = 3600`), поэтому изменения в базе появляются не мгновенно.
